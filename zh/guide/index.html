使用指南

怎么录制、怎么定位、怎么定时，以及那些容易让人意外的地方。

本指南讲那些按钮上看不出来的事：定位到底怎么起作用、为什么固定延时不如等待、每种自动启动 方式各自的代价，以及任务失效时该从哪里查。

开始之前

有两个权限是必需的，各自负责一件具体的事：

  • 无障碍服务——它才是真正执行点击与手势的能力，也是 clicktap 读取所需控件 的前提。未开启则回放完全无法工作。
  • 悬浮窗（显示在其他应用上层）——录制悬浮条与录制时的捕获层需要它。

另外三个是可选的，只有用到对应功能时才有意义：

  • 通知使用权——供「消息触发」读取通知文本。
  • 闹钟和提醒——让定时执行更准时，未开启时系统可能延迟触发。在 Android 14 及以上，锁屏提醒要自动亮屏还需要「全屏通知」特殊权限；未授予时提醒仍会响铃与震动。
  • 忽略电池优化——减少后台执行被系统中断的可能。

权限需在系统设置中开关，应用内不能直接授予：点击开关会进入对应的设置页，返回后状态自动刷新。

录制一段任务

  1. 点击「开始录制」，会出现一条悬浮条。
  2. 然后就像平时那样操作你要自动化的应用。你的操作会被记录同时执行，下层应用仍会 正常响应——你并不是在操作一块死掉的屏幕。
  3. 随时可在悬浮条上暂停或结束。
  4. 给任务起个名字。名字只是个标签，不影响回放。

多指手势

用两根以上手指画出这个手势，全部抬起即录完一条，最多支持三指。手势轨迹由录制生成，不能 逐指手改——要改就重录。如果手势需要干净的屏幕，可以在白屏上录制。

一个动作如何找到它的目标

每个动作都有定位方式。这是决定任务能否长期可用的最大因素，值得认真设置。

按控件定位

最可靠的方式。可以按资源 ID、按可见文本、或按内容描述匹配，多个条件还能用「与 / 或」组合。 最好的填写方式是在真实界面上点选控件、让 clicktap 自己读出来，而不是手打。

关于只用文本匹配：文本与描述按"包含"匹配，所以文案小幅变化仍能命中；但当目标应用使用稳定的 控件 ID 时，把文本与 ID 配对会更稳。

按坐标定位

坐标按屏幕比例记录，而不是像素，所以在一台手机上录制的任务，通常换一台不同分辨率的手机 也能用。但请把它当兜底方案：它无法判断屏幕是否处于你预期的状态。

按文字识别（OCR）定位

当控件没有可用的 ID 时用它——画布类界面、网页视图、游戏。

  • 你可以在屏幕上框选最多三块区域，区域内识别到的文字会列出来供一点即填。
  • 点击落在命中文字的中心。同一区域内命中多处时，取离你框选时点的那个位置最近的一处。
  • 多块区域之间是"或"的关系，按顺序找，第一个命中就停。
  • 匹配忽略大小写，包含即算命中。
  • 轮询间隔默认 500，可填 350–2000。下限来自系统截屏节流（约 3 次/秒），不是识别速度——填更小 会被系统直接拒绝。等待页面出现需要 Android 11 及以上，因为它依赖系统截屏接口。

等待页面出现，而不是死等

动作可以先等目标真的出现再点击。这正是能不能扛住开屏广告的区别：固定延时往往等广告都过去了 才醒来，然后点了个空。

等待超时是"最长找多久"。开屏广告场景建议从 8000 左右开始试。填 0 表示不等待，动作立即执行。

文字识别也是同样的思路：填 0 只识别一次；填大于 0 会按上面的间隔反复重识别，直到文字出现。 页面需要等一下才能出来时用它。

循环与流程图

可以把连续的动作组成循环，最多重复五次，且支持嵌套。循环是连续的一段动作，因此循环之间不能 交叉。当循环体内的动作定位失败时，你可以选择后果：中止整次回放，或丢掉本轮剩余步骤、继续 下一轮。

流程图视图把同一个任务画成图，一旦用上循环，它比一长串列表好检查得多。

自动启动

任务可以自己运行，共三种方式。同一任务同一时刻只能启用一种，手动运行则始终可用。

  • 定时触发——选择星期与时间。还要决定回放的起点：先回桌面（推荐）、先打开 目标 App，或就停在当前界面直接回放。
  • 消息触发——选择 App 与关键词。通知的标题或正文包含任一关键词即触发。可以 让 clicktap 先点开该通知，让回放从正确的页面开始；通知不支持打开时自动降级为按起点执行。 一个提醒：若来源 App 关闭了消息预览，只能读到占位文本（如"收到 1 条新消息"），你的关键词 不会命中。
  • 从 App 启动——选择一个或多个 App，以及要监听哪些窗口事件。"窗口或页面 切换"通常就是"App 打开了"的信号。也可以监听界面内容变化，但要清楚代价：该事件在滚动、 刷文案、动画时会极频繁上报，无障碍服务会被连续唤醒，容易卡顿、更耗电。回放间隔控制同一 次 App 会话内两次回放之间至少间隔多久，冷却期内的事件会被记为跳过。

定时任务在灭屏或锁屏时到点，可以唤醒设备并提醒你，方式是震动或响铃——也可以是你自己选的 铃音文件。

执行日志

一份日志同时回答你真正关心的两个问题：这次为什么没执行，以及回放到哪一步失败了。记录按 执行场次分组，长时间静默会切分场次之间的日志段。可以记录每一步的细节，也可以只看失败。

调试模式会在自动重放时显示回放浮窗，并在录制与回放时叠加手势轨迹，是看清"点到底落在哪" 最快的方式。手动重放不受此设置影响，始终显示浮窗。

备份、导入与回放脚本

  • 备份。单个任务或勾选多个任务都能导出为 .clicktap 文件，换设备 导入即可。格式是一个 zip，内含一份清单与每个任务一个 JSON 文件，以及你为任务附加的自定义 提醒铃音。
  • gkd 规则。可导入 gkd 的 JSON5 格式订阅规则，支持 URL 或文件，导入后按 "常驻自动匹配"运行。可在规则列表里对每个订阅或规则组单独启停。
  • 分享。公开的任务包按原样存储与公开，不做任何剥离——包括步骤备注、匹配到的 屏幕文本、通知关键词、目标包名，以及内嵌的提醒铃音。发布前请先读隐私政策第六条，并利用发布页给出的清单逐项确认。
  • 导入他人的包。clicktap 在导入时会关闭触发开关，所以导入的任务不会自己 跑起来。运行前请先读一遍它的步骤。

任务失效时怎么办

几乎总是下面几种，按这个顺序查：

  1. 应用改界面了。在执行日志里找到失败的那一步，重新定位它。换皮时控件 ID 比 文本更能扛。
  2. 屏幕不在你预期的位置。给失败步骤的前一步加上或加大等待超时，或者把起点 设为"先回桌面"。
  3. 权限或电池设置变了。系统更新后有时会关掉无障碍服务；看首页的运行状态。
  4. 出现了录制时没见过的弹窗。把它关掉的那一下录一遍，用 ID 或文本定位，并给 足够长的等待。

clicktap 不需要 root，支持 Android 10 及以上。文字识别需要 Android 11 及以上。各受支持版本 上的行为保持一致。

在真实界面上点选控件更不容易填错。仍可以手打 ID、文本或描述。
